# T-002 — iOS: Screen Time core loop on James's iPhone

**Goal:** an iPhone app that asks for Screen Time access once, hides Instagram and TikTok by bundle identifier when James taps "Start class mode," and brings them back automatically at a scheduled end time — without a server.

**Why:** this is the riskiest mechanism in the product and the one Apple constrains most. If bundle-identifier hiding works on a real phone today, the whole engine design holds. Proving it first, with nothing else attached, is the cheapest possible test. Read `docs/ios.md` before starting.

**Scope — in:** the `TapIn` app target + the `TapInMonitor` DeviceActivityMonitor extension, generated by XcodeGen; authorization; hide/unhide by bundle id; scheduled unhide via DeviceActivity; a minimal SwiftUI screen. **Out:** NFC, VPN (T-003), networking, onboarding screens, the demo's visual design (a plain screen is fine here).

## Steps
1. Create `apps/ios/project.yml` (XcodeGen) with two targets — see `docs/ios.md` for bundle ids, capabilities and entitlements. Deployment target iOS 17.0. Automatic signing with James's team (`DEVELOPMENT_TEAM` from `xcodebuild -showBuildSettings` after he signs into Xcode, or leave for Xcode to fill on first open — report which). Entitlement files checked into git. App Group `group.com.tapinschools.tapin` on both targets.
2. `xcodegen generate`; open the project once so Xcode registers the App ID and capabilities (James may need to click "Try again" under Signing & Capabilities — put that in the physical steps).
3. App screen (SwiftUI, plain): authorization status line; **Allow Screen Time** button → `AuthorizationCenter.shared.requestAuthorization(for: .individual)`; **Start class mode (15 min)** button; **End class mode now** button; a countdown label.
4. `ClassMode` service (shared code, App Group aware):
   - `apply(bundleIds:)` → `ManagedSettingsStore(named: .init("classMode")).application.blockedApplications = Set(ids.map(Application.init(bundleIdentifier:)))`
   - `clear()` → `blockedApplications = nil`
   - bundle ids for this test: `com.burbn.instagram`, `com.zhiliaoapp.musically`, `com.toyopagroup.picaboo` (Snapchat), `com.google.ios.youtube`. Put the list in one file with a `// DEVELOPMENT ONLY — served by the policy API from T-007` header.
5. Scheduling: on "Start class mode," call `apply` immediately **and** `DeviceActivityCenter().startMonitoring(.classMode, during: DeviceActivitySchedule(intervalStart: now, intervalEnd: now + 15 min, repeats: false))`. In `TapInMonitor`, subclass `DeviceActivityMonitor`: `intervalDidStart` → `apply` (idempotent), `intervalDidEnd` → `clear()` + `stopMonitoring`. Verify the minimum interval rule in Apple's docs and note it in the report.
6. Stretch (only if 1–5 pass): add a second screen with `FamilyActivityPicker` and shield the selection via `store.shield.applications` — the fallback path — so we know both mechanisms work on this phone and iOS version. Label it clearly as the fallback.
7. Build for James's device from the terminal (`xcodebuild ... -destination 'platform=iOS,name=…'`) and install (`xcrun devicectl`), or hand off to Xcode's Run button — write whichever worked into `docs/local-development.md`.
8. Session-end ritual: report, `docs/PROGRESS.md`, branch `task/T-002-ios-screen-time-core-loop`, PR.

## Finish line
On James's iPhone: tap Allow → Face ID → status "approved"; tap Start → Instagram and TikTok disappear from the Home Screen and App Library within seconds; wait 15 minutes with the app closed → they return on their own; "End class mode now" also returns them immediately.

2. Run the app from Xcode on your phone. If Xcode shows a signing error, open the TapIn target → Signing & Capabilities → click "Try again" / enable the capability it names.
